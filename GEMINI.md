# CHA Design System

Storybook documentation and visual regression tests for the City of Chattanooga design system, built from Figma with the `figma-storybook` skill located in `.agents/skills/figma-storybook/` (and `.claude/skills/figma-storybook/`).

- **Figma source of truth (working copy)**: https://www.figma.com/design/nMenOGxGYRL0pyDAc0ZmFF/CHA-Design-System--Copy-
- **Progress, component status and open design questions**: `design-system/manifest.json`
- **Latest reports**: `design-system/reports/figma-changes.md`, `design-system/reports/token-audit.md`

## Multi-Agent Execution & Concurrency

You are equipped to run multiple agents concurrently to accelerate project workflows:
- **Subagents (`invoke_subagent`)**: When processing component batches (e.g. 5–10 components at a time), launch parallel subagents to handle independent components concurrently (e.g. one subagent builds `Button` while another handles `Input`).
- **Swarm Mode (`/swarm` or swarm plugins)**: Use Swarm orchestration for broad sweeps, audits, or parallel test suites across the repository.
- **Model Selection**: Default to Claude Opus (`claude-opus-4-6-thinking`) for complex reasoning and design-to-code generation, or delegate simpler research/lookup tasks to subagents.

## Every Session

1. **Figma Sync Check (Step 0)**:
   - Start with the sync check from `figma-storybook` before other work, even when the prompt is about another topic.
   - If `figmaSync` in `design-system/harness.config.json` is `paused`, skip the sync check, make no Figma calls, and note that Storybook reflects the last snapshot.
   - Summarize what changed in Figma before proceeding, then rebuild anything marked `stale`.

2. **Token Audit**:
   - Run the token audit whenever design context is read from Figma.
   - Unbound values are reported for the design team to fix in Figma—never silently change or invent values in code.

## Design Harness

This repo is the source of truth for design across all products. Code is built from Figma design context, retrieved via the Figma MCP tools (`get_design_context`) and persisted under `design-system/figma/`.

- **Before modifying a component**: Run `npm run harness -- context <Component>`.
- **Never invent design details**: If context is missing, flag the gap in the manifest notes.
- **After building**: Run `npm run harness:check`. Commit `design-system/reports/harness-log.jsonl` and `harness-log.md` with the work.
- **Enforcement mode**: `contextEnforcement` in `harness.config.json` defaults to `warn` until Figma access is confirmed, then `block`. Only change when requested.

## Technical Conventions

- **Stack**: React 19 + TypeScript + Vite, Storybook 10, plain CSS per component.
- **Tokens**: Components MUST only use CSS variables in `src/tokens/tokens.css` (generated by editing `design-system/tokens.figma.json` and running `npm run tokens`).
- **Breakpoints**: Figma `Screen = Desktop | Mobile` variants are handled as breakpoints (`src/styles/responsive.css`), not as props.
- **Interaction States**: Hover, focus, active states are handled via CSS, with stories exposed via `storybook-addon-pseudo-states`.
- **AllVariants Matrix**: Every component must have an `AllVariants` story mirroring its Figma component set for visual regression testing.
- **Visual Baselines**: Created using the Playwright Docker setup (never on bare Windows).
- **Figma Rate Limits**: Starter plan limits MCP calls; budget calls conservatively and flag blocked unread components in `manifest.json`.
